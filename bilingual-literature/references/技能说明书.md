## 一、这个技能是做什么的

把外文文献整理成“原文一句、译文一句”的对照稿，保留原文档的标题、段落、图片、脚注、链接、列表和表格结构，并可以导出：

- Word 文档
- PDF
- 纯文本
- Notion Markdown
- 分级词汇表或全量词汇表（Word、Excel）

它不是普通聊天翻译，而是带抽取、切句、翻译工作单、装配、验收和词表导出的本地工具链。

## 二、适用对象

适合需要把论文、讲义、书稿做成中外对照稿的人；需要保留图片、脚注和标题层级的人；需要按 HSK、CEFR、JLPT 等分级导出词表的人；需要 Word、PDF 或 Notion Markdown 成品的人。

不适合只想要一句普通翻译、只想看摘要、或完全没有文件读写和 Python 执行环境的纯聊天客户端。

## 三、语言范围

源语言：中文、意大利语、英语、德语、法语、西班牙语、俄语、日语、拉丁语。

目标语言：中文、意大利语。

有效方向：九种源语言乘两种目标语言，减去两种同语对，共十六对。主对是意大利语到中文、中文到意大利语；其余为二等尽力而为。拉丁语和日语属于二级方向。

## 四、输入与输出

输入支持 Word、PDF、TXT、Markdown。扫描版 PDF 需要先用 OCR 处理。

输出支持双语 Word、双语 PDF、纯文本、双语 Markdown、Notion Markdown、词汇表 Word 和 Excel。

## 五、安装环境

需要 Python 3.10 或更高版本。安装依赖：

~~~powershell
python -m pip install -r bilingual-literature/references/requirements.txt
~~~

可选外部工具：

- LibreOffice：Word 转 PDF
- Tesseract OCR：扫描 PDF
- eSpeak NG：离线 IPA
- spaCy 及语言模型：意大利语、英语、德语、法语、西班牙语词形
- pymorphy3：俄语词形
- pykakasi、fugashi、UniDic-lite：日语罗马字和分词

检查本机工具：

~~~powershell
python bilingual-literature/scripts/run.py check-tools
~~~

## 六、最短工作流

以下命令在发行目录下执行。

### 1. 抽取结构

~~~powershell
python bilingual-literature/scripts/run.py extract source.docx out/source.json
~~~

### 2. 切分句子

现代文：

~~~powershell
python bilingual-literature/scripts/run.py split-units out/source.json out/units.json
~~~

文言文或古文：

~~~powershell
python bilingual-literature/scripts/run.py split-units out/source.json out/units.json --classical
~~~

--classical 会按逗号、分号、冒号切成更短的句子，避免整段只对应一条译文。

### 3. 生成工作单

~~~powershell
python bilingual-literature/scripts/run.py outline out/units.json out/outline.md
python bilingual-literature/scripts/run.py worklist out/units.json out/work.json
~~~

结构确认使用技能内的 SKILL.md 规则；必要时把结构覆盖写入 structure.json。

### 4. 导出翻译批次

~~~powershell
python bilingual-literature/scripts/run.py translate export out/work.json out/tr
~~~

在 out/tr 下按批次填写译文，例如 tr_c1.json 的 translations 字段。

### 5. 合并译文

~~~powershell
python bilingual-literature/scripts/run.py translate merge out/work.json out/tr --out out/translations.json
~~~

### 6. 生成双语 Markdown

~~~powershell
python bilingual-literature/scripts/run.py build-blm --work out/work.json --translations out/translations.json --out out/bilingual.md
~~~

### 7. 验收 Markdown

~~~powershell
python bilingual-literature/scripts/run.py verify-md --work out/work.json --md out/bilingual.md
~~~

### 8. 生成 Word

~~~powershell
python bilingual-literature/scripts/run.py build-docx out/bilingual.md out/final.docx
~~~

### 9. 生成 PDF

~~~powershell
python bilingual-literature/scripts/run.py to-pdf out/final.docx out/final.pdf
~~~

### 10. 验收 Word

~~~powershell
python bilingual-literature/scripts/run.py verify out/source.json out/final.docx
~~~

## 七、完整工作流建议

对长文档，不要一次把全文塞进一次翻译。

1. 先抽取结构；
2. 确认标题层级和正文范围；
3. 生成句级工作单；
4. 按批次导出、翻译、合并；
5. 每一批都跑 verify-md；
6. 最后装配 Word 和 PDF；
7. 需要词表时再单独做词表。

长文档按 SKILL.md 的分批规则处理，不要在上下文里硬塞全文。

## 八、字号、标题与颜色

- 字号由源文档驱动，不写死绝对磅数。
- 中文目标译文：约等于源字号减两磅，最低八磅。
- 意大利语目标译文：与源字号相同。
- 译文颜色：深蓝色 #1F4E79。
- 不使用斜体。
- 中文目标译文使用楷体；意大利语目标使用 Times New Roman。
- 中文源文的 Word 使用宋体，日语源文使用 Yu Mincho，避免 LibreOffice 导出 PDF 时缺字。
- 中文源到意大利语目标时，标题拆成源文行和译文行；长标题自动分行。
- 标题字号不单调时回退为 22、18、16、14、13 磅。

这些规则写在 style-profiles.json 和 build_docx.py 中，调用时不需要手写字号。

## 九、词表

### 先预检

~~~powershell
python bilingual-literature/scripts/run.py vocab precheck --lang it --system CEFR --db vocab/vocab.db
~~~

预检会检查分词器、词形还原器、发音组件和分级数据是否已初始化。不通过时只给三个选择：补依赖、跳过词表、终止。不会生成缺词的半成品。

### 初始化分级库

~~~powershell
python bilingual-literature/scripts/run.py vocab init --lang it --system CEFR --db vocab/vocab.db
~~~

只初始化用户指定的语言和体系，不批量下载所有语言。

### 分级词表

~~~powershell
python bilingual-literature/scripts/run.py vocab extract --md out/bilingual.md --lang it --target zh --system CEFR --min B1 --db vocab/vocab.db --out out/doc.vocab.json
~~~

### 全量词表

任意语言：

~~~powershell
python bilingual-literature/scripts/run.py vocab extract --md out/bilingual.md --lang it --target zh --all --out out/doc.all.json
~~~

--all 会跳过分级过滤，所有词都进表，level 为 ALL。

拉丁语默认全量，不需要传 --all：

~~~powershell
python bilingual-literature/scripts/run.py vocab extract --md out/bilingual.md --lang la --target zh --out out/la.all.json
~~~

### 补译

~~~powershell
python bilingual-literature/scripts/run.py vocab fill --words out/doc.vocab.json --translations dictionary.json --out out/doc.filled.json
~~~

字典键可以使用原型或原文。

### 导出 Word 和 Excel

~~~powershell
python bilingual-literature/scripts/run.py vocab build --words out/doc.filled.json --format word --out out/vocab.docx
python bilingual-literature/scripts/run.py vocab build --words out/doc.filled.json --format excel --out out/vocab.xlsx
~~~

## 十一、客户端兼容

- WorkBuddy：上传 bilingual-literature 文件夹
- Claude Code、Claude.ai Skills：使用 SKILL.md
- Cursor、Codex、DSH（DeepSeek Harness）：读取 SKILL.md 并运行 Python
- Gemini Apps Skills：只支持文本上传，不适合完整 Python 流水线
- 豆包工作桌面端：要求根目录小写 skill.md；当前 PC 包使用大写 SKILL.md，需要小写包装
- 豆包移动端：不支持自定义技能
- 纯聊天客户端：只能按 SKILL.md 人工执行，不能自动生成 Word、PDF 或词表

## 十二、验收和降级

状态分三种：PASS、PASS_DEGRADED、FAIL。

允许降级的情况只有图片缺失、脚注缺失、句对跨页。失败时必须修复，不能把失败稿当成交付稿。

## 十三、常见问题

1. 没有 PDF：先安装 LibreOffice，并运行 check-tools 确认。
2. 扫描版 PDF 没文字：用 OCR 流程；俄语需要 Tesseract 和 rus.traineddata。
3. 中文 PDF 乱码：确认 build_docx.py 使用宋体作为中文源文字体，再用 LibreOffice headless 重新导出。
4. 词表缺失：先跑 vocab precheck；缺什么补什么，不要用 skip-precheck 生成半成品。
5. 长文翻译被截断：按批次处理，不要一次塞全文；使用工作单和续跑。
6. 输出文件已存在：技能会自动改名 _v2、_v3，不覆盖已有交付。
